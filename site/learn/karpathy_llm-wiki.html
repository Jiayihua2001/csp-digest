karpathy_llm-wiki

· () · 0 citations
> Karpathy's gist describing a pattern for using LLM agents to build and maintain a personal knowledge base in markdown — the seed source for this vault.

Takeaways

- The wiki is a persistent, compounding artifact, not a query-time RAG cache. Knowledge is compiled once on ingest and kept current, not re-derived per question. - Three layers: immutable raw sources, an LLM-owned wiki of summaries / entity / concept pages, and a schema file (e.g. `CLAUDE.md`) that encodes conventions. - Three operations: ingest (read source → write/update pages → update index/log), query (consult index → read pages → answer with citations → optionally file the answer back as a synthesis page), lint (find contradictions, orphans, stale claims, missing pages). - Two special files: `index.md` (content-oriented catalog, the routing layer) and `log.md` (chronological, append-only, greppable with consistent prefixes). - Division of labor: the human curates sources and asks questions; the LLM does all the bookkeeping — summarizing, cross-referencing, filing. - Obsidian is the recommended reader; the LLM is the writer; the wiki is plain markdown in a git repo, getting version history and branching for free. - Optional tools: [[entities/qmd|qmd]] for hybrid search at scale, Marp for slide-deck output, Dataview for frontmatter-driven queries, Obsidian Web Clipper for ingesting web articles. - Conceptual lineage: explicitly riffs on [[concepts/memex|Vannevar Bush's Memex (1945)]] — the missing piece in Bush's vision was *who maintains the trails*, and LLMs solve that.

Summary

Karpathy frames the gist as an idea file — meant to be pasted into an LLM agent that will then collaborate with the user to instantiate the specifics. The core argument is that mainstream LLM-over-documents tools (NotebookLM, ChatGPT file uploads, generic RAG stacks) re-derive knowledge from raw chunks on every query and never accumulate structure. The proposed alternative is to put a persistent wiki between the user and the raw sources: a directory of interlinked markdown pages that the LLM incrementally builds and maintains. The architecture is three layers. Raw sources sit immutable in their own directory — articles, papers, images, data. The wiki is the LLM-owned layer of summaries, entity pages, concept pages, comparisons, syntheses. The schema (a `CLAUDE.md` or `AGENTS.md`) encodes conventions and workflows so the LLM behaves like a disciplined wiki maintainer rather than a generic chatbot. The schema is co-evolved with the user over time. Three operations structure the work. Ingest is the workhorse: when a source arrives, the LLM reads it, discusses takeaways with the user, writes a summary page, updates the index, and propagates changes to relevant entity and concept pages — a single source might touch 10–15 pages. Query answers questions against the wiki rather than against raw sources, with citations, and crucially the answers themselves can be filed back into the wiki as new pages so explorations compound. Lint is a periodic health check for contradictions, orphans, stale claims, missing pages, broken cross-references. Two files anchor navigation. `index.md` is content-oriented — a catalog of every page organized by category, used by the LLM as the routing layer when answering queries. `log.md` is chronological — append-only, with a consistent header prefix so it can be grepped for recent activity. Karpathy notes that this approach scales surprisingly well to ~100 sources / hundreds of pages without needing embedding-based RAG infrastructure. The "Optional CLI tools" section recommends [[entities/qmd|qmd]] for hybrid BM25/vector search once the wiki outgrows the index file. Tips and tricks cover the practical Obsidian setup: [[entities/obsidian|Obsidian]] Web Clipper for capturing web pages, configuring an attachment folder so images download locally (since LLMs can't always read inline-image markdown in one pass), the graph view for spotting orphans and hubs, Marp for slides, Dataview for frontmatter queries, and the observation that the wiki being plain markdown in git gives version history "for free." The "Why this works" section is the central thesis: humans abandon wikis because maintenance burden grows faster than value. LLMs don't get bored, don't forget cross-references, and can edit 15 files in one pass — so maintenance becomes near-zero-cost, and the wiki stays alive. The closing note draws an explicit line to [[concepts/memex|Vannevar Bush's Memex]]: a private, curated knowledge store with associative trails between documents, where the trails matter as much as the documents. Bush couldn't solve who builds and maintains those trails. The LLM does. The final "Note" insists the document is intentionally abstract — a description of the *pattern*, not an implementation. Directory layout, schema conventions, page formats, and tooling all depend on the user's domain and preferences, and are expected to be worked out in collaboration with the agent.
